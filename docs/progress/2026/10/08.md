# Progress — 2026-10-08

## [2026-10-08] incident: official posts auto-publish (`LIVE`) + console `hidden` filter

- **What**: two product-policy changes on the official-post/feed surface.
  1. **Official ingestion is now auto-approved**: `ingest_posts` creates rows
     `SocialMediaLinkStatus.LIVE`, not `PENDING_APPROVAL`, so an operator's own
     announcement is public immediately — no admin action sits between the tweet
     and the feed. The pre-create existence checks (`(socmed_account, post_id)`
     and `normalized_url`) are unchanged, so a re-ingest skips an existing row
     and an admin who later `HIDE`s an official row is never overridden.
  2. **The console queue gains a tri-state visibility filter**:
     `socialMediaLinks(hidden: Boolean)` — omitted keeps the console's
     long-standing all-statuses default (`HIDDEN` included, so an admin can find
     one to un-hide it), `true` returns only `HIDDEN`, `false` excludes `HIDDEN`.
     This powers the console's show/hide-hidden-entries control.
- **Migration `0032_autoapprove_official_links`** (data-only, no model change):
  one `UPDATE` flipping `is_automated=True, status="pending_approval"` to
  `"live"`. Raw string values are used deliberately (a historical model's field
  is whatever the state at `0031` declared, and an enum rename must not change
  what the migration writes). Reverse is `RunPython.noop`: which rows were flipped
  is not knowable afterwards, and re-pending them would resurrect the old policy
  and hide already-published posts. `HIDDEN` rows are never touched; community
  links are out of scope by the `is_automated` filter.
- **The public-feed automated-pending gate stays, as a defensive net.** The feed
  still excludes `is_automated=True, status=PENDING_APPROVAL` (and the per-row
  `is_publicly_visible` predicate still mirrors it), but with ingestion writing
  `LIVE` this now catches only a legacy/imported automated row still parked in
  the old approval state — it is no longer the publish path. The docstrings on
  `get_public_social_media_links` and the exclusion comment now say so.
- **Telegram notification copy no longer lies**: `_build_notification_text` says
  "New official post — published" and links to the console to *review*, and the
  "Reply to this message with `/approve` to publish it." line is gone. The
  `TelegramSocialMediaLinkLog` write, the escaping and the 4096-character budget
  are untouched. The `/approve` handler was already safe for a `LIVE` row (it
  answers "Link is not awaiting approval." and does not write), so it is
  unchanged; the join row is still written so a reply resolves (as a no-op).
- **SDL snapshot**: purely additive — the one changed line is the new
  `hidden: Boolean` argument on `Query.socialMediaLinks`. `find_breaking_changes`
  does not flag an added optional arg, so `EXPECTED_ACCEPTED_BREAKING_CHANGES`
  is untouched.
- **Tests**: 5 new gate-visible Django-unittest tests in `incident/tests.py`
  (`OfficialPostAutoPublicationTests` — ingested row is `LIVE` and appears on
  `publicSocialMediaLinks`; `AutoApproveOfficialLinksBackfillTests` — automated
  pending → `LIVE`, automated hidden stays `HIDDEN`, community pending stays
  `PENDING_APPROVAL`; `ConsoleQueueHiddenFilterTests` — omitted/true/false through
  the real schema). Existing assertions updated to expect `LIVE` for ingested rows
  (verbatim-mapping test, fixture command, webhook delivery) and the notification
  copy assertions updated (header, console text, no `/approve`). A pytest-tree
  migration test (`tests/incident/test_autoapprove_official_links_backfill.py`)
  and a resolver-level `hidden` test (`tests/incident/test_social_media_link_mutations.py`,
  beside `test_admin_resolver_filters`) mirror the surrounding files. The existing
  `ApproveHandlerTests.test_admin_reply_to_live_link_prompts_not_awaiting_approval`
  already pins the `/approve` no-op on a `LIVE` row.
