## Telegram: `/spotting_today` referenced a non-existent `VehicleStatus` member

- **What**: `telegram_provider/utils.py::get_daily_updates` excluded
  `vehicle__status=VehicleStatus.NOT_IN_SERVICE`, an attribute that does not exist on
  `operation.VehicleStatus` (the member there is `OUT_OF_SERVICE`; only
  `spotting.SpottingVehicleStatus` keeps a `NOT_IN_SERVICE` member). The exclusion now uses
  `VehicleStatus.OUT_OF_SERVICE`, so the default `/spotting_today` digest and the 03:00
  `spotting.tasks.report_spotting_today` push render again.
- **Why**: `/spotting_today` in the TranSPOT Test channel raised
  `AttributeError: type object 'VehicleStatus' has no attribute 'NOT_IN_SERVICE'` at
  `utils.py:238`; the flag (and this reference) landed in `0882c80` and never ran against a
  real out-of-service roster in tests.
- **Tests**: `telegram_provider/tests.py::GetDailyUpdatesTests` (real ORM, no mocks) — the
  default digest omits an `OUT_OF_SERVICE` vehicle, `include_not_in_service=True` lists it.
  `ruff check`/`ruff format` clean; `manage.py check` clean; 55-test `telegram_provider`
  suite → 50 pass (5 pre-existing `LinkHandlerTests` Firebase-env errors, confirmed present
  with the change stashed).
