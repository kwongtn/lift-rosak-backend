## Telegram: `/spotting_today` referenced a non-existent `VehicleStatus` member

- **What**: `telegram_provider/utils.py::get_daily_updates` excluded
  `vehicle__status=VehicleStatus.NOT_IN_SERVICE`, an attribute that does not exist on
  `operation.VehicleStatus` (the member there is `OUT_OF_SERVICE`; only
  `spotting.SpottingVehicleStatus` keeps a `NOT_IN_SERVICE` member). The exclusion now uses
  `VehicleStatus.OUT_OF_SERVICE`, so the default `/spotting_today` digest and the 03:00
  `spotting.tasks.report_spotting_today` push render again.
- **Why**: `/spotting_today` in the TranSPOT Test channel raised
  `AttributeError: type object 'VehicleStatus' has no attribute 'NOT_IN_SERVICE'` at
  `utils.py:238`; the flag (and this reference) landed in `0882c80` and never ran against a
  real out-of-service roster in tests.
- **Tests**: `telegram_provider/tests.py::GetDailyUpdatesTests` (real ORM, no mocks) — the
  default digest omits an `OUT_OF_SERVICE` vehicle, `include_not_in_service=True` lists it.
  `ruff check`/`ruff format` clean; `manage.py check` clean; 55-test `telegram_provider`
  suite → 50 pass (5 pre-existing `LinkHandlerTests` Firebase-env errors, confirmed present
  with the change stashed).
- **Commit**: 6075118.

## Telegram: `/spotting_today` service-day cutoff (3am default)

- **What**: `/spotting_today` now resolves "today" through a configurable day cutoff:
  anything before 03:00 (in `settings.TIME_ZONE`) counts as the previous calendar day, so a
  command run at 02:59 on 24 Sep reports 23 Sep. New flags: `--use-actual-date` (12am
  cutoff) and `--cutoff=HHMM` (24-hour custom cutoff, e.g. `--cutoff=0430`); the two are
  mutually exclusive, malformed values reply with a usage error, and an explicit positional
  date is never shifted. `utils.effective_spotting_date(now, cutoff)` is the pure helper;
  `get_daily_updates` and every other caller are untouched (its rendered header still uses
  `date.today()`, deliberately out of scope).
- **Tests**: `EffectiveSpottingDateTests` (boundary, aware/naive, month/year rollover),
  `SpottingTodayHandlerTests` (cutoff selection, timezone of `now`, explicit-date
  precedence, invalid cutoff, mutual exclusion), `LinkHandlerTests` parser cases (HHMM
  parsing, malformed rejection, exclusivity). 17/17 targeted tests pass; 74-test
  `telegram_provider` suite → 69 pass (same 5 pre-existing `LinkHandlerTests`
  Firebase-env errors, confirmed on the stashed baseline). `ruff check`/`ruff format`
  clean; `manage.py check` clean.
- **Commit**: 42d8b12.
