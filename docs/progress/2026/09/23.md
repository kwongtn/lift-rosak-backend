## Incident: admin-only `deleteSocialMediaLink` mutation

- **What**: `SocialMediaLinkMutations` (`incident/schema/mutations/interactions.py`) gains
  `deleteSocialMediaLink(socialMediaLinkId: ID!): GenericMutationReturn!`, decorated
  `@strawberry.mutation(permission_classes=[IsAdmin])`. It delegates to
  `incident/services/social_links.py::delete_social_media_link(user, *, link_id, is_admin: bool = False)`,
  which now skips the submitter-ownership check when `is_admin=True` (the same service still backs the
  submitter path). The schema snapshot (`rosak/tests/snapshots/schema.graphql`) was regenerated with the
  one added field. No model or migration change.
- **Why**: admins could `markSocialMediaLinkCompleted` but had no way to remove a bad feed link —
  deletion was only reachable through the submitter-ownership path.
- **Tests**: `incident/tests.py::SocialMediaLinkTests.test_delete_social_media_link_admin_deletes_another_users_link`
  (admin deletes another user's link) and `..._requires_admin` (non-admin rejected, link kept);
  `tests/incident/test_schema_build.py`'s expected mutation set was extended with
  `delete_social_media_link`. `manage.py check` clean; the four targeted tests pass with `--keepdb`;
  `ruff check`/`ruff format` clean.
