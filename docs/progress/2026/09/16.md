# 2026-09-16

## Incident: submitter edit of SocialMediaLink — role rule + forced re-approval (Task 24)

- **What**: `update_social_media_link` now enforces the role rule that the public link edit flow
  relies on: admin edits land LIVE (status/completed preserved), a submitter's edit goes back
  into the approval queue (forces `status=PENDING_APPROVAL`, `completed=False`,
  `completed_at=None`, `completed_by=None`). Submitters may edit only their own links
  (`IncidentServiceError` otherwise).
- **Why**: The frontend edit affordance (canEditLink: author shortId match or admin) is a UI
  gate; the backend rule is the authoritative one.
- **How**:
  - `incident/services/social_links.py` — `update_social_media_link(user, *, is_admin, link_id,
    write)` gains the ownership check + force-pending logic; omitted `incident_id` now preserves
    the existing association (deliberate fix — previously the submit-only path set
    `incident_id=None`).
  - `incident/schema/mutations/interactions.py` — the field went from `IsAdmin` to `IsLoggedIn`;
    `is_admin` resolved from `rosak.permissions` and passed down.
  - `tests/incident/test_social_media_link_mutations.py` — 2 existing tests updated to pass
    `is_admin=True`; 3 new tests (admin keeps live, submitter forced pending, ownership
    rejection).
- **Validated**: `ruff check` + `ruff format --check` + `py_compile` on the three files — all
  pass. DB-backed Django tests NOT run in this environment (no docker/PostGIS/pytest here) —
  unverified, reported honestly.

## Telegram: media uploads always record a TemporaryMedia row, even while uploads disabled

- **What**: `handlers.media` no longer returns early when `should_upload_media()` is false
  ("no response" paths). It computes `uploads_disabled`, records it in
  `metadata["uploads_disabled"]`, and still creates the `TemporaryMedia` row (PENDING /
  AWAITING_REVIEW / TRUSTED_CLEARED as usual). The conversion task already re-checks the
  feature flag, so the row simply queues until uploads are re-enabled (cleanup task picks it
  up). Reply on the disabled path: "Media received, but uploads are currently disabled. It
  will be published once uploads are re-enabled."
- **Validated**: `MediaHandlerTests.test_feature_flag_off_queues_temp_media_and_replies`
  (replaced the old create-nothing test) passes in-container.

## Telegram: /approve on a replied /link message approves the link

- **What**: `handlers.approve` falls back to `TelegramSocialMediaLinkLog` lookup when no
  AWAITING_REVIEW media matches the reply. A pending-approval link is set to LIVE
  (`SocialMediaLinkStatus.LIVE`, `update_fields=["status"]`) and "Approved. Link is now live."
  is sent; a non-pending link replies "Link is not awaiting approval."
- **Validated**: `ApproveHandlerTests` gains 2 tests (pending link approved, live link
  rejected); existing `test_admin_reply_with_no_awaiting_review_media_prompts` keeps passing
  under the new link-log mock default.
